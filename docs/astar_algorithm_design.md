# A* (A-Star) Algorithm Design

**Status:** Phase 7D — Complete (implemented and verified)

---

## 1. Algorithm Overview

A* is a best-first search algorithm that uses a **heuristic function** to guide exploration toward the destination. It combines the cost-so-far (g) from Dijkstra with a heuristic estimate (h) of the remaining cost:

```
f(node) = g(node) + h(node)
```

where:
- `g(node)` = actual cost from source to `node` (same as Dijkstra)
- `h(node)` = heuristic estimate of cost from `node` to destination
- `f(node)` = total estimated cost through `node`

### When A* Is Optimal

A* is guaranteed to find the optimal (lowest-cost) route when:
1. **Admissibility:** `h(node)` never overestimates the true remaining cost (`h(n) ≤ h*(n)` for all n)
2. **Consistency (monotonicity):** `h(n) ≤ c(n, n') + h(n')` for every edge `(n, n')`

All three implemented heuristics (Zero, Euclidean, Manhattan) satisfy both properties.

### Relationship to Dijkstra

A* with `h(n) = 0` (ZeroHeuristic) is **exactly Dijkstra's algorithm**:
- `f(n) = g(n) + 0 = g(n)` → priority queue orders by g-value
- Same node expansion order, same result, same complexity

This is verified by the test suite: `AStarRouting(heuristic=ZeroHeuristic)` produces identical routes and costs as `DijkstraRouting()` on every test graph.

## 2. Heuristic Architecture

### 2.1 Heuristic Protocol

```python
class Heuristic(Protocol):
    """Interface that every heuristic function must satisfy."""

    @property
    def name(self) -> str:
        """Stable heuristic name for logging and configuration."""
        ...

    def estimate(
        self,
        source: NodeId,
        destination: NodeId,
        graph: DirectedGraph,
    ) -> float:
        """Estimate remaining cost from source to destination.

        Must be admissible (never overestimate) for A* optimality.
        Must be consistent (monotonic) for A* efficiency.
        """
        ...
```

### 2.2 Implemented Heuristics

| Heuristic | Formula | Admissible | Consistent | Notes |
|-----------|---------|------------|------------|-------|
| `ZeroHeuristic` | `h(n) = 0` | Yes | Yes | Degenerate; A* becomes Dijkstra |
| `EuclideanHeuristic` | `h(n) = scale × √((x₂−x₁)² + (y₂−y₁)²)` | Yes | Yes | Best for continuous coordinates |
| `ManhattanHeuristic` | `h(n) = scale × (|x₂−x₁| + |y₂−y₁|)` | Yes | Yes | Best for grid/taxicab geometry |

All heuristics support an optional `scale` factor (default 1.0) for tuning heuristic strength. Scaling preserves admissibility when `scale ≤ 1.0`.

### 2.3 HeuristicFactory

```python
class HeuristicFactory:
    @staticmethod
    def create(name: str, **kwargs) -> Heuristic:
        """Create a heuristic by name.

        Supported names: 'zero', 'euclidean', 'manhattan'.

```

Supports `astar/heuristic_name` syntax in the routing factory (e.g., `create_algorithm("astar/euclidean")`).

### 2.4 HeuristicValidator

```python
class HeuristicValidator:
    @staticmethod
    def check_admissibility(
        heuristic: Heuristic,
        graph: DirectedGraph,
    ) -> HeuristicValidationReport:
        """Verify h(n) ≤ actual shortest-path cost for all nodes."""

    @staticmethod
    def check_consistency(
        heuristic: Heuristic,
        graph: DirectedGraph,
    ) -> HeuristicValidationReport:
        """Verify h(n) ≤ c(n, n') + h(n') for all edges."""
```

## 3. A* Algorithm Details

### 3.1 Core Search Procedure

```
1. Initialize:
   - priority_queue ← [(f(source), tie_breaker, source)]
   - g_score[source] ← 0
   - came_from ← empty

2. While priority_queue not empty:
   a. Pop node n with smallest f(n)
   b. If n == destination, reconstruct and return path
   c. Mark n as explored
   d. For each outgoing edge (n → n'):
      - Skip if edge is blocked or n' already visited with lower g
      - tentative_g ← g(n) + cost(n → n')
      - If tentative_g < g(n'):
        - Set g(n') ← tentative_g
        - f ← tentative_g + heuristic(n', destination)
        - Push (f, tie_breaker, n') onto queue
        - Set came_from[n'] ← n

3. If queue exhausted without reaching destination:
   - Return failure (no path exists)
```

### 3.2 Key Implementation Details

- **Heap:** `heapq` (min-heap by f-value)
- **Tie-breaking:** Sequential counter ensures deterministic ordering when f-values are equal
- **Visited set:** Dictionary mapping `NodeId → g-score` (replaces closed set; allows re-opening if better g found)
- **Timeouts:** `time.perf_counter()` checks; graceful `RoutingTimeoutError` failure
- **Blocked edges:** Skipped during neighbor expansion (infinite-cost edges)
- **Multiple candidates:** Generated by iteratively blocking edges of primary route (same as Dijkstra)
- **Statistics:** `nodes_explored`, `edges_explored`, `candidates_generated` collected during search

### 3.3 Candidate Generation

Same as Dijkstra: after finding the primary route, A* iteratively blocks each edge along the primary route and re-runs the search. This produces alternative routes for the Decision Engine.

## 4. Complexity Analysis

### 4.1 Time Complexity

| Metric | Value | Notes |
|--------|-------|-------|
| Worst-case | O(E + V log V) | Same as Dijkstra (when heuristic provides no guidance) |
| Best-case | O(E) | Heuristic guides directly to goal |
| Average | O(E) | With admissible, consistent heuristic |

where V = number of nodes, E = number of edges.

### 4.2 Space Complexity

| Metric | Value | Notes |
|--------|-------|-------|
| Priority queue | O(V) | At most one entry per node |
| Visited set | O(V) | g-score per node |
| Came-from map | O(V) | Path reconstruction |
| **Total** | **O(V)** | Proportional to node count |

### 4.3 Comparison with Dijkstra

| Aspect | Dijkstra | A* |
|--------|----------|-----|
| Priority | g(n) only | g(n) + h(n) |
| Explored nodes | All nodes with g < C* | Nodes with g + h < C* |
| Optimality | Always | With admissible h |
| Best case | O(E + V log V) | O(E) |
| Worst case | O(E + V log V) | O(E + V log V) |

where C* = optimal path cost.

## 5. Heuristic Theory

### 5.1 Admissibility Proof

**EuclideanHeuristic:** The straight-line distance is the shortest possible path between two points in Euclidean space. Any actual path through the graph must be at least as long as the straight-line distance. Therefore `h_euclidean(n) ≤ h*(n)` for all n.

**ManhattanHeuristic:** On a grid with axis-aligned movement, the Manhattan distance is the shortest path when no diagonal movement is allowed. Any actual path must be at least as long. Therefore `h_manhattan(n) ≤ h*(n)` for all n.

**ZeroHeuristic:** `h(n) = 0 ≤ h*(n)` for all n (trivially admissible).

### 5.2 Consistency Proof

**EuclideanHeuristic:** By the triangle inequality: `dist(A, C) ≤ dist(A, B) + dist(B, C)`. For any edge `(A, B)` with cost `c(A, B) ≥ dist(A, B)` and destination `C`: `h(A) = dist(A, C) ≤ dist(A, B) + dist(B, C) ≤ c(A, B) + h(B)`. Therefore consistent.

**ManhattanHeuristic:** Same triangle inequality argument applies to Manhattan distance.

**ZeroHeuristic:** `0 ≤ c(n, n') + 0 = c(n, n')` (trivially consistent since costs ≥ 0).

### 5.3 Effect on Search Efficiency

The stronger the heuristic (closer to true cost), the fewer nodes A* explores. The heuristic is **perfect** when `h(n) = h*(n)` for all n on the optimal path, causing A* to explore exactly the nodes on the optimal path.

```python
# Direct construction

algorithm = AStarRouting(heuristic=EuclideanHeuristic(scale=0.5))
```

### 7.2 Benchmark Integration

The `BenchmarkRunner` runs A* without modification:
```python
config = BenchmarkConfig(algorithm_names=["astar"])
runner = BenchmarkRunner(config)
results = runner.run_scenario(scenario)
```

### 7.3 Verifier Integration

The `RoutingVerifier` validates A* results using the same algorithm-independent checks as Dijkstra:
- `verify_route(route, graph)` — validates path validity
- `verify_result(result, graph, request)` — validates result structure
- `verify_cost_breakdown(candidate)` — validates cost consistency
- `verify_deterministic_replay(algorithm, request, graph)` — validates determinism
