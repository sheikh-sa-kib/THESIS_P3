## 3. Network File (Immutable)

The network file `data/maps/midtown_manhattan.net.xml` was generated with:

```
netconvert --osm-files manhattan.osm --output-file midtown_manhattan.net.xml
  --proj.utm --geometry.remove --roundabouts.guess
  --tls.discard-simple --tls.join --tls.guess-signals
  --ramps.guess --keep-edges.in-geo-boundary -74.000,40.745,-73.970,40.765
  --keep-edges.by-vclass passenger --remove-edges.isolated
  --no-internal-links --junctions.join
```

- **SUMO version**: 1.27.1
- **Schema version**: 1.16
- **Date generated**: 2026-05-09

This file must never be modified. Any network changes invalidate all prior experiment results. Store a checksum:

```
SHA256 (midtown_manhattan.net.xml) = <record in metadata.json>
```

## 4. Route File (Reproducible Generation)

The route file is generated by `randomTrips.py` then `duarouter`:

**Step 1 — Generate random trips:**

```bash
python "SUMO_HOME\tools\randomTrips.py"
  -n data\maps\midtown_manhattan.net.xml
  -r data\routes\midtown_manhattan.rou.xml
  --end 60.0 --period 2.0 --seed 42
```

**Step 2 — Compute shortest-path routes:**

```bash
duarouter -n data/maps/midtown_manhattan.net.xml
  -s trips.trips.xml -o data/routes/midtown_manhattan.rou.xml
  --routing-threads 2 --begin 0 --end 60.0
```

The route file used in experiments was generated with **seed 42** by `randomTrips.py` and `duarouter` v1.27.1.

Reproducing the route file requires the same randomTrips seed AND the same SUMO/duarouter version, as routing heuristics may differ between versions.

## 5. Simulation Seeds

| Seed | Used For |
|------|----------|
| `sumo_seed = 42` | SUMO internal randomisation (traffic light phases, car-following noise) |
| `benchmark_seed = 42` | Routing request generation, algorithm random seeds |

Both seeds are configurable in `SumoConfig` and `BenchmarkConfig` respectively.

## 6. Algorithm-Specific Parameters

| Algorithm | Parameters | Deterministic? |
|-----------|-----------|----------------|
| Dijkstra | (none) | Yes — always produces same route for same topology |
| A* | `heuristic = "euclidean"` | Yes — deterministic with fixed heuristic |
| ACO | `n_ants=20, max_iterations=100, alpha=1.0, beta=2.0, rho=0.1, seed=42` | Yes — seed controls all random choices |
| BCO | `n_bees=15, max_iterations=50, seed=42` | Yes — seed controls all random choices |
| PSO | `n_particles=30, max_iterations=50, w=0.7, c1=1.5, c2=1.5, seed=42` | Yes — seed controls all random choices |
| E3-Hybrid | `n_aco=10, n_bco=10, n_pso=10, max_iterations=30, seed=42` | Yes — seed controls all sub-algorithms |

All algorithms receive the same seed from `RoutingFactory`. The factory injects this seed into each algorithm's random number generator.

## 7. Verifying Deterministic Behaviour

The benchmark framework verifies deterministic replay via `RoutingVerifier.verify_deterministic_replay()`:

```python
from e3hybrid.routing.verifier import RoutingVerifier
report = RoutingVerifier.verify_deterministic_replay(algo, request, graph)
assert report.is_valid
```

This runs the algorithm twice with a deep copy of the graph and asserts that costs, routes, and success status are identical.

## 8. Configuration Snapshot

Every experiment run writes a `config_snapshot.yaml` containing the exact `SumoConfig` and `BenchmarkConfig` used. This is a byte-level record — no interpretation or defaulting occurs at read time.

## 9. Experiment Runner Invariants

```
run_experiment.py --seed 42 --steps 300 --vehicles 300 --algorithms dijkstra,astar,aco,bco,pso,e3hybrid
```

Must produce bit-identical CSV output across runs on the same machine with the same SUMO version.

**Cross-platform reproducibility** is not guaranteed due to:
- Floating-point differences in cost computation across CPU architectures
- SUMO behaviour may differ between Windows and Linux
- Python dict iteration order is stable in >=3.7 but hash seed differs
